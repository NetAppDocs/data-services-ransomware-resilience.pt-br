= Configurar a detecção de atividade do usuário em NetApp Ransomware Resilience
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Utilize a detecção de comportamento do usuário do NetApp Ransomware Resilience para identificar atividades suspeitas que possam indicar ransomware, violação de dados ou eventos de destruição de dados. Para habilitar, instale pelo menos um agente de atividade do usuário para criar o ambiente de coleta de dados.

Um agente de atividade do usuário hospeda um coletor de dados e um conector de diretório de usuários, que enviam dados para um local na nuvem para análise.

* O **coletor de dados** coleta dados de atividade do usuário do ONTAP. O coletor de dados é criado automaticamente quando você cria uma estratégia de proteção com detecção de comportamento do usuário.
* O **conector de diretório de usuários** se conecta ao seu diretório para mapear IDs de usuário a nomes de usuário. Você deve configurar o conector de diretório de usuários.


O agente de atividade do usuário, o coletor de dados e o conector do diretório de usuários podem ser gerenciados a partir do painel de configurações de Ransomware Resilience.

Se você não estiver usando o NetApp Data Infrastructure Insights (DII), siga as instruções de configuração aqui.



[[before-you-begin]]
== Antes de começar

* Certifique-se de cumprir os link:reference-user-activity-requirements.html["sistema operacional, requisitos de servidor e de rede"].


*Função de console necessária* Para ativar a detecção de comportamento do usuário, você precisa da **função de administrador da organização**. Para configurações subsequentes de detecção de comportamento do usuário, você precisa da **função de administrador de comportamento do usuário de Ransomware Resilience**. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-ransomware-roles.html["Saiba mais sobre as funções de resiliência contra ransomware para o NetApp Console"^].

Garanta que cada função seja aplicada no nível organizacional.



[[considerations-for-data-infrastructure-insights-dii-workload-security-users]]
=== Considerações para usuários do Workload Security do Data Infrastructure Insights (DII)

Se você já utiliza NetApp Data Infrastructure Insights (DII) Workload Security, use os mesmos agentes do Workload Security para a Resiliência a Ransomware. Você não precisa implantar agentes separados do Workload Security para a Resiliência a Ransomware. No entanto, usar os mesmos agentes do Workload Security exige uma relação de emparelhamento entre a organização do Console de Resiliência a Ransomware e o tenant do DII Storage Workload Security. Entre em contato com seu representante de conta para habilitar esse emparelhamento.

Ao ativar a detecção de atividade do usuário no Ransomware Resilience, o sistema usa as credenciais atualmente salvas no Console para gerenciar seus coletores de dados. Se você já havia habilitado a detecção de atividade do usuário por meio do Data Infrastructure Insights (DII) Workload Security, as credenciais do Console substituirão as que você usava anteriormente no DII para gerenciar os coletores de dados.



[[create-a-user-activity-agent]]
== Crie um agente de atividade do usuário

Os agentes de atividade do usuário são ambientes executáveis para link:#add-a-data-collector["coletores de dados"] que compartilham eventos de atividade do usuário com o Ransomware Resilience. Você deve criar pelo menos um agente de atividade do usuário para habilitar a detecção de atividade do usuário.


NOTE: Após a criação do locatário, não é possível alterar a região. A criação do locatário leva aproximadamente cinco minutos e não pode ser cancelada depois de iniciada.

.Passos
Você pode criar um agente de atividade do usuário usando uma configuração *Manual* ou *Automática*. Com a configuração automática, você precisa fornecer o agente do Console, o nome DNS da VM ou endereço IP e a chave SSH da VM para que o Ransomware Resilience possa criar o tenant. Com a configuração manual, o Ransomware Resilience fornece os comandos para criar o tenant manualmente.

[role="tabbed-block"]
====
.Manual
--
. Se esta for a primeira vez que você cria um agente de atividade do usuário, acesse o **Dashboard**. No bloco **User activity monitoring**, selecione **Activate**.
+
Se você estiver adicionando um agente adicional de atividade do usuário, acesse *Configurações*, localize o bloco **Monitoramento de atividade do usuário** e selecione **Gerenciar**. Na tela de atividade do usuário, selecione a guia **Agentes de atividade do usuário** e, em seguida, **Adicionar**.

. Selecione um **provedor de nuvem** e, em seguida, uma **região**.
. Selecione **Criar locatário**.
+
O processo de criação de locatário leva aproximadamente cinco minutos. Após selecionar *Criar locatário*, você pode selecionar *Executar em segundo plano* para retornar ao painel e continuar com outras operações.

. Insira o *nome do agente de atividade do usuário*.
. Selecione *Manual* como método de configuração.
. Na etapa *Permitir locatário*, o Ransomware Resilience fornece a URL do agente de atividade do usuário. Copie e cole a URL para permitir conexões.
. Abra um terminal no seu ambiente de nuvem para instalar o agente de atividade do usuário.
+
.. Opcionalmente, se você estiver usando um servidor proxy, preencha a variável do seu servidor proxy e execute o comando de exportação mostrado. `export https_proxy='USER:PASSWORD@PROXY_SERVER:<port>'`. Se o servidor proxy não exigir autenticação, omita os campos de usuário e senha. Nesse caso, o comando será semelhante `export https_proxy='https://proxy.company.com:<port>'`.
.. No mesmo terminal, copie e cole o comando de instalação. O trecho de código é válido por apenas duas horas e só pode ser usado para instalar um agente de atividade do usuário.
+
Caso você precise instalar agentes adicionais de atividade do usuário, repita esse processo para gerar um novo trecho de instalação.



. Selecione *Avançar*.
. Analise os detalhes do agente de atividade do locatário e do usuário. Se tudo estiver correto, selecione *Ativar* para concluir o processo.


--
.Automático
--
. Se esta for a primeira vez que você cria um agente de atividade do usuário, acesse o **Dashboard**. No bloco **User activity monitoring**, selecione **Activate**.
+
Se você estiver adicionando um agente adicional de atividade do usuário, acesse *Configurações*, localize o bloco **Monitoramento de atividade do usuário** e selecione **Gerenciar**. Na tela de atividade do usuário, selecione a guia **Agentes de atividade do usuário** e, em seguida, **Adicionar**.

. Selecione um **provedor de nuvem** e, em seguida, uma **região**.
. Selecione **Criar locatário**.
+
O processo de criação de locatário leva aproximadamente cinco minutos. Após selecionar *Criar locatário*, você pode selecionar *Executar em segundo plano* para retornar ao painel e continuar com outras operações.

. Digite um nome para o *nome do agente de atividade do usuário*.
. Selecione *Automático* como método de configuração.
. Forneça os detalhes do agente de atividade do usuário:
+
** *Agente de console* - O agente de console deve estar na mesma rede que o agente de atividade do usuário e ter conectividade SSH com o endereço IP do agente de atividade do usuário.
** *Nome DNS ou endereço IP da VM*
** *Chave SSH da VM* - Insira a chave SSH usando este formato:
+
[code]
----
-----BEGIN OPENSSH PRIVATE KEY-----
private-key-contents
-----END OPENSSH PRIVATE KEY-----
----
+
image:user-activity-agent.png["Captura de tela da interface do agente de adição de atividade."]



. Selecione **Avançar**.
. Revise suas configurações. Selecione *Ativar* para concluir a adição do agente de atividade do usuário.
. Confirme se o agente de atividade do usuário foi criado com sucesso. No bloco de monitoramento de atividade do usuário, uma implantação bem-sucedida é exibida como **Em execução**.


--
====
.Resultado
Após a criação bem-sucedida do agente de atividade do usuário, retorne ao menu **Configurações** e selecione **Gerenciar** no bloco de monitoramento de atividade do usuário. Selecione a guia **Agentes de atividade do usuário** e selecione o agente de atividade do usuário para visualizar detalhes sobre ele, incluindo coletores de dados e conectores de diretório de usuários.



[[add-a-data-collector]]
=== Adicionar um coletor de dados

Os coletores de dados são criados automaticamente quando você ativa uma estratégia de proteção contra ransomware com detecção de atividade do usuário. Para obter mais informações, consulte link:rp-use-protect.html#add-a-detection-policy-to-workloads-with-existing-backup-or-snapshot-policies["adicionar uma política de detecção"].

Você pode visualizar os detalhes do coletor de dados. Em Configurações, selecione **Gerenciar** no bloco Monitoramento de atividade do usuário. Selecione a guia **Coletor de dados** e, em seguida, selecione o coletor de dados para visualizar seus detalhes ou pausá-lo.

image:user-activity-settings.png["Captura de tela das configurações de atividade do usuário."]



[[delete-a-data-collector]]
=== Excluir um coletor de dados

Se um coletor de dados estiver obsoleto ou não estiver mais funcionando, você pode excluí-lo. Qualquer carga de trabalho monitorada pelo coletor de dados deixará de ser monitorada em busca de comportamentos suspeitos do usuário após você excluí-lo.

.Passos
. Em Ransomware Resilience, vá para *Configurações*.
. No bloco de monitoramento de atividades do usuário, selecione **Gerenciar**.
. Selecione a aba *Agentes e coletores* e depois *Coletores de dados*.
. Identifique o coletor de dados que você deseja excluir. Selecione o menu de ações e depois **Excluir**.
. Na caixa de diálogo, selecione *Excluir* para confirmar.




[[create-a-user-directory-connector]]
== Criar um conector de diretório de usuários

Para mapear IDs de usuário para nomes de usuário, você deve criar um conector de diretório de usuário.

.Passos
. Em Ransomware Resilience, vá para *Configurações*.
. No bloco de monitoramento de atividades do usuário, selecione **Gerenciar**.
. Selecione a guia *Agentes e coletores*, depois a guia **Conectores de diretório de usuários** e, em seguida, **Adicionar**.
. Configure a conexão. Insira as informações necessárias em cada campo.
+
[cols="25,75"]
|===
| Campo | Descrição 


| *Nome* | Insira um nome exclusivo para o conector do diretório de usuários. 


| *Tipo de diretório de usuário* | O tipo de diretório 


| *Endereço IP do servidor ou nome de domínio* | O endereço IP ou o nome de domínio totalmente qualificado (FQDN) do servidor que hospeda a conexão 


| *Nome da floresta ou nome da pesquisa*  a| 
Você pode especificar o nível da floresta na estrutura de diretórios como o nome de domínio direto (por exemplo, `unit.company.com`) ou um conjunto de nomes distintos relativos (por exemplo: `DC=unit,DC=company,DC=com`). Você também pode inserir um `OU` filtrar por uma unidade organizacional ou um `CN` limitar a um usuário específico (por exemplo: `CN=user,OU=engineering,DC=unit,DC=company,DC=com`).



| *LIGAR DN* | O DN BIND é uma conta de usuário com permissão para pesquisar no diretório, como por exemplo, user@domain.com. O usuário precisa da permissão "Somente leitura" para o domínio. 


| *Senha BIND* | A senha do usuário fornecida em BIND DN 


| *Protocolo* | O campo de protocolo é opcional. Você pode usar LDAP, LDAPS ou LDAP sobre StartTLS. 


| *Porta* | Insira o número da porta escolhida. 
|===
+
image:screenshot-user-directory-connection.png["Captura de tela da conexão do diretório do usuário"]

+
Forneça os detalhes do mapeamento de atributos:

+
** *Nome de exibição*
** *SID* (se você estiver usando LDAP)
** *Nome de usuário*
** *ID Unix* (se você estiver usando NFS)
** Se selecionar *Incluir atributos opcionais*, você também poderá adicionar um endereço de e-mail, número de telefone, função, estado, país, departamento, foto, DN do gerente ou grupos.


. Selecione *Advanced* para adicionar uma consulta de pesquisa opcional.
. Selecione **Adicionar**.
. Retorne à guia de conectores do diretório do usuário para verificar o status do seu conector do diretório do usuário. Se criado com sucesso, o status do conector do diretório do usuário será exibido como *Em execução*.




[[delete-a-user-directory-connector]]
=== Excluir um conector de diretório de usuário

.Passos
. Em NetApp Ransomware Resilience, selecione *Configurações*.
. Localize o bloco de monitoramento de atividade do usuário, selecione **Gerenciar**.
. Selecione a aba **Conector de diretório do usuário**.
. Identifique o conector de diretório do usuário que você deseja excluir. No menu de ação no final da linha, selecione os três pontos `...` então **Excluir**.
. Na janela pop-up, selecione **Delete** para confirmar.
