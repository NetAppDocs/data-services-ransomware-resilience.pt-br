= Requisitos de detecção de atividade do usuário para NetApp Ransomware Resilience
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
A detecção de atividade do usuário do NetApp Ransomware Resilience permite que você responda a eventos de ransomware no nível do usuário. Você precisa criar um tenant e um conjunto de agentes para habilitar a detecção de atividade do usuário. Antes de habilitar a detecção, você deve garantir que atenda aos requisitos de sistema operacional, servidor e rede descritos para que o NetApp Ransomware Resilience possa detectar e relatar eventos corretamente.



[[user-activity-tenant]]
== Tenant de atividade do usuário

Para habilitar a detecção de atividades do usuário, um tenant é configurado para permitir que eventos de atividade do usuário sejam compartilhados com o Ransomware Resilience. Você pode selecionar a região e o provedor de nuvem onde deseja que o Ransomware Resilience implante o tenant.


NOTE: A implantação regional do locatário não afeta o agente do Console. A implantação do agente do Console é independente dessas regiões.

O locatário pode ser implantado na AWS e no Azure nas seguintes regiões:

|===
| Provedor de nuvem | Região 


| AWS  a| 
* Ásia-Pacífico (Sydney) (ap-sudeste-2)
* Europa (Frankfurt) (eu-central-1)
* Leste dos EUA (Norte da Virgínia) (us-east-1)




| Azul | Leste dos EUA 
|===


[[user-activity-agent-requirements]]
== Requisitos do agente de atividade do usuário

Após a criação do locatário, você deve criar um agente de atividade do usuário para habilitar a detecção de atividade do usuário. O agente de atividade do usuário não é o agente do Console; ele precisa ser implantado como uma instância de computação separada.

Certifique-se de que seu agente de atividade do usuário atenda aos seguintes requisitos e siga as recomendações.



[[operating-system-requirements]]
=== Requisitos do sistema operacional

A detecção de comportamentos suspeitos do usuário é compatível com os seguintes sistemas operacionais:

|===

| Debian | 11 (64 bits), 12 (64 bits), incluindo SELinux

| SUSE Linux Enterprise Server | 15 SP4 (64 bits) a 15 SP6 (64 bits), incluindo SELinux

NOTE: A máquina que você usa para o agente de atividade do usuário não deve estar executando nenhum outro software de nível de aplicativo. Um servidor dedicado é recomendado.

O  `unzip`comando é necessário para instalação. O  `sudo su -`comando é necessário para instalação, execução de scripts e desinstalação.



[[server-requirements]]
=== Requisitos do servidor

O servidor deve atender aos seguintes requisitos mínimos:

* **CPU**: 4 núcleos
* **RAM**: 16 GB de RAM
* **espaço de disco**: 36 GB livres




==== Recomendações do servidor

* Aloque espaço de disco extra para permitir a criação do sistema de arquivos. Certifique-se de que haja pelo menos 35 GB de espaço livre no sistema de arquivos. + Se `/opt` for uma pasta montada do armazenamento NAS, os usuários locais devem ter acesso a essa pasta. A criação do agente de atividade do usuário pode falhar se os usuários locais não tiverem as permissões necessárias.
* Instale o agente de atividade do usuário em um sistema separado do seu ambiente do Ransomware Resilience. Se você instalar o agente e o Ransomware Resilience na mesma máquina, reserve de 50 a 55 GB de espaço de disco. Para Linux, aloque de 25 a 30 GB de espaço para `/opt/netapp` e 25 GB para `/var/log/netapp`.
* Recomenda-se sincronizar a hora tanto no sistema ONTAP quanto na máquina do agente de atividade do usuário usando o Protocolo de Tempo de Rede (NTP) ou o Protocolo de Tempo de Rede Simples (SNTP).




==== Recomendações de dimensionamento

Ao coletar eventos de usuário, certifique-se de que a máquina que hospeda o agente de atividade do usuário esteja dimensionada para acomodar sua taxa de eventos. Isso significa garantir que você tenha coletores de dados suficientes e CPU e RAM suficientes na máquina que hospeda o agente de atividade do usuário para lidar com o número de eventos por segundo. Para aumentar o número de coletores de dados, pode ser necessário aumentar a capacidade de RAM ou CPU. O Ransomware Resilience oferece suporte a até 50 coletores de dados por agente de atividade do usuário.

A tabela a seguir fornece orientações gerais para dimensionamento:

|===
| Configuração da máquina do agente de atividade do usuário | Número de coletores de dados | Taxa máxima de eventos 


| 4 núcleos, 16GB | 10 coletores de dados | 20.000 eventos/segundo 


| 4 núcleos, 32GB | 20 coletores de dados | 20.000 eventos/segundo 
|===
Você também pode calcular suas necessidades específicas. Ao calcular o tamanho adequado, recomenda-se qualificar com uma taxa de buffer de 30%. Use esta fórmula para determinar se sua configuração pode lidar com a carga.

====
O Ransomware Resilience fornece um script que você pode executar em seu sistema para calcular a taxa de dados de eventos. Por padrão, o script é executado para no máximo cinco SVMs. Se o seu ambiente incluir mais de cinco SVMs, você pode modificar o script de acordo. Independentemente do número de SVMs, o script leva aproximadamente cinco minutos para obter uma leitura da taxa média de eventos. Antes de executar o script, você deve ter:

* link:suspicious-user-activity.html["Configurou um agente de atividade do usuário"]
* O endereço IP do cluster
* Nome de usuário e senha do administrador do cluster
* Instalado `sshpass` na máquina Linux (você pode instalar usando o comando `sudo yum install -y sshpass`)


.Passos
. A partir da máquina que hospeda o agente de atividade do usuário, execute o script como administrador: `/opt/netapp/cloudsecure/agent/install/svm_event_rate_checker.sh`
. Quando solicitado, forneça o endereço IP do cluster, o nome de usuário do administrador e a senha do administrador.
. O script leva aproximadamente cinco minutos para ser executado. Ao terminar, a linha de comando exibe a taxa de eventos, por exemplo "Svm svm_rate está gerando 100 eventos/seg."
+
Use a taxa de eventos para calcular o dimensionamento.
